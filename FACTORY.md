# The Adversary Line

A software factory of five coding-agent seats in Band Desktop. One person sends one message; the seats plan, build, verify, audit their own verification, and close each stage — with no further human input. In the submitted run that one message produced all four stages of the event's tablekeeper track.

It runs entirely on free models from OpenCode Zen, which need no account and no key. Standing it up costs nothing but a machine.

## The seats

| Seat | Owns | Never | Harness / model |
|---|---|---|---|
| **Foreman** | the plan, every handoff, every open decision, the stage freeze, the final report | writes product code; asks the human anything | OpenCode / `opencode/big-pickle`; `opencode/space-bunny-free` while that one is capped |
| **Builder** | service internals, build files, run instructions | accepts its own work | OpenCode / `opencode/big-pickle`; `opencode/space-bunny-free` while that one is capped |
| **Finisher** | every surface a person sees: visual system, states, accessibility, widths | accepts its own work; touches service internals | OpenCode / `opencode/big-pickle`; `opencode/space-bunny-free` while that one is capped |
| **Adversary** | a requirements ledger written before any code exists; its own probes; the verdict | edits product code; trusts an unreproduced claim | OpenCode / `opencode/big-pickle`; `opencode/space-bunny-free` while that one is capped |
| **Saboteur** | planting known defects in scratch copies and counting what the checks catch | changes the real product | OpenCode / `opencode/nemotron-3-ultra-free` |

Each seat's standing instructions are in `mandates/<seat>.md`. None of them names anything about the problem being built; the problem arrives only in the dispatch.

## Rules the runtime enforces, not just the mandates

Practice runs showed that a model will break a written rule when it is in a hurry. So the rules that matter most are enforced by the seat's runtime, which refuses the tool call and says why. The launcher (`bin/seat.jail`) generates each seat's runtime configuration when it starts:

| Rule | Enforced by | Why |
|---|---|---|
| No subagents | the runtime's subagent tool is removed | A coordinator once started a hidden helper that wrote code under the coordinator's name, in parallel with the real builder. Work done in a seat must be that seat's, under its name, and reported in the room |
| The supplied check files cannot be opened, listed or printed | refused by path, and as a folder to change into, for every seat | Code must come from the specification; seats run the checks and read only the results. In the 1–2 October run the Finisher got round the path rule ten times, by changing into the specification package first and naming the files relatively (see "A side door to the check files"); that way is refused too now. In the submitted run the runtime refused 12 attempts by three seats, and no seat read a check file |
| The Foreman, the Adversary and the Saboteur cannot change the product, and no seat commits outside its own area | the edit tool is refused by path inside a stage folder for the Foreman and the Adversary; for all three the jail mounts the repository read-only except its history and the seat's own folder; the commit hook refuses any file outside the committing seat's area | Seats that plan, judge or attack never change the product. The edit rule alone was not enough: in the 1–2 October run the Foreman rewrote two product files with a script (see "A planner that went around its rule"); the hook kept it from committing them, and the read-only mount now stops the write itself. In the submitted run the same mount kept the Foreman's own stage-4 sabotage round out of the repository, and how the Foreman got round that is in "Planted defects left in the product" |
| A message with newlines, backticks or `$(` on a command line is refused | refused by pattern, for every seat | The shell runs backticks as commands, so an inline handoff arrives gutted; long messages go from a file with `--body-file`. In the 1–2 October run the rule did not hold for a send that named the seat's own session (see "A rule that a later rule undid"); the rules now come in the order that makes it hold |
| Each seat sees only the work area and the specification, read-only, and has its own `/tmp` and its own process space; the work area's root is read-only, so a seat writes only inside the run's repository and `checks/` | a `bwrap` jail | Keys, other projects and earlier runs are invisible, and nothing a seat writes lands where another seat or the next run would take it for its own. A seat that restarts its server with `pkill` reaches only its own processes, never another seat's runtime, the key proxy or Band |
| Each seat commits only its own area: the Adversary `verification/`, the Saboteur `verification/sabotage/`, the Builder and Finisher the stage folders; the Foreman commits nothing. Bulk staging (`git add -A`, `git add .`, `commit -a`) and skipping hooks are refused | a read-only `pre-commit` hook every seat's git uses (`bin/seat-hooks/`), plus refused commands | A seat that staged everything committed two other seats' unfinished files under its own name; the history must show who wrote what |
| Only the Builder moves the result repository's checkout | a read-only `post-checkout` hook (`bin/seat-hooks/`): another seat's checkout there is undone, and the command fails with the command for a private clone | Every seat works in the one checkout. A checker on a new model checked out an older commit there to verify it: the builder's files moved under it, and the checker, not finding its own ledger at that commit, began a new one. Seats look at other commits in their own clone under `/tmp` |
| Unreadable model output never reaches the room | `bin/acp-quiet` | The free gateway occasionally returns degenerate text — Latin shot through with several unrelated scripts. It is replaced by one line asking the sender to resend, so the room stays readable and the run does not stall waiting for a reply that never comes |
| A turn that has nothing to say is posted as nothing | `bin/acp-quiet`, between Band and the runtime | Band posts a seat's closing text as a reply, and a reply wakes the sender. Models cannot end a turn with no text, so they write "No reply needed." — which wakes the other seat, which answers "Silent completion." Seats now close such a turn with the single word SILENT, and the filter drops exactly that (and the handful of phrases seen in practice, or a short text that opens by saying no reply is needed — "*Silent turn — the status was already posted*" — or a short closing line in a turn that has already posted its message through the band CLI, such as "Handoff sent (message 40d4a6f1).", or a closing text of any length there that opens by saying the message went out — "Verdict sent. Summary: …", a second copy of the message that woke the other seat again four times in one practice run), so Band records a silent completion A short one-line text that only announces the seat's next step ("Now I'll add the test cases.", "Now sending the verdict.") is an acknowledgement by another name: as a closing text it is dropped, and before a tool call it is posted as a thought, still visible, so it no longer wakes the seat it names (calibrated on 111 distinct texts from every saved practice room: it flags exactly the three such lines). And when the runtime compacts a long session, the summary it writes for itself (a fixed template: Objective, Important Details, Work State, Next Move, Relevant Files) is withheld wherever it appears: twice in one practice morning a coordinator's 10 KB private notes were posted as its reply, and the seat they named took them for a brief (the template matched exactly those two of 179 saved texts). Every other reply passes through unchanged; checked against every message the seats posted in a practice room, it settles only the three that explained their own silence |
| The human's message is never answered with silence | `bin/acp-quiet`: a turn that answers a message from the human and ends with nothing — or only SILENT — without having called a tool is sent back once, in the same session, before Band sees an answer | The first attempt at the 1–2 October run ended in its first minute: the coordinator answered the four-stage dispatch with only SILENT, and since the dispatch is the only human input, nothing would ever have woken it. That room was abandoned unsubmitted and the run started again in a fresh room and repository |
| No key ever enters a seat | `bin/key-proxy`, outside every jail | A seat can run shell commands, what it prints can reach the room, and the room's log is published with the result. So a seat on a keyed provider gets no key: its runtime talks to a local proxy that holds the key, adds it, and forwards only the model list and chat completions. Checked from inside a jail: no environment variable, config file or visible file holds a key |
| A seat whose model is rate-limited carries on with a second model, or pauses — it never drops out | `bin/acp-quiet`, `bin/wake-seats` | The free gateway cuts a model off once a run has used enough of it, with no hint of when it lifts. The runtime gives up after a minute and fails the turn, and Band then stops that seat's runtime. The filter holds the failed turn open, posts one visible "paused, resumes about HH:MM" note, waits with growing pauses (3, 6, 12, 20, then 30 minutes), and asks the runtime to carry on in the same session. Band sees one long turn; the seat's work is not lost. When the provider does name a time — the free gateway's usage cap says ten hours, though the model came back after about three — the runtime waits that long inside the turn. `bin/wake-seats`, outside the jails, reads each seat's runtime log; for a seat whose last request was refused and which has been quiet since, it asks the model for one word, and once the model answers it signals the seat's filter, which cancels the wait and resumes the turn in the same session. Tested end to end with the real runtime against a server that refuses with a one-hour wait. A seat whose mandate names a second model (`Fallback model:`, on a separate quota) does not wait at all: a turn that fails on a rate limit resumes at once on the second model, and a turn waiting inside the runtime is moved to it within seconds: the filter reads its own runtime's log and acts on the refusal (`bin/wake-seats` does the same from outside after three quiet minutes, as a backstop). The switch is one protocol call (`session/set_config_option`): same session, same history, same tools; the room gets one note naming both models. While the seat works on its second model, `bin/wake-seats` asks its own model every quarter of an hour, and once it answers the seat's next turn goes back to it. One request getting through does not prove a cap has lifted — in a practice run a probe answered while four resumed seats were refused two seconds later — so a seat just refused on one model tries the other first, and each return that is refused again doubles the wait before the next (a quarter of an hour, up to two hours). Tested end to end with the real runtime while the first model was capped: the stuck turn resumed and answered on the second model within two seconds |
| What a seat leaves running is removed | `bin/mem-guard` (a user service) and one line in each seat's mandate | Seats start a service or a container for every check, and many never stop them: one practice stage left 14 containers and 25 service processes running, the 7 GB laptop's memory and swap filled, and the desktop client itself was killed. Mandates now say to stop what you start; the guard removes, every minute, a process orphaned inside a seat's jail or a container that has been up 15 minutes (5 when memory is low, 2 when it is critical) and has used no CPU for as long; each orphaned service held about 270 MB. The idle test came from the 1–2 October run: the laptop sat just under the low-memory line, and the first guard removed the Adversary's service six minutes into probing it. Anything busy is removed only after 45 minutes (10 when memory is critical), and the event harness's own containers, which it removes itself, meet only that cap. The seat's runtime, its filter and the command it is running are never touched. The cost: a seat that comes back to a service it left idle starts it again, in seconds. It is not enough on its own: in the submitted run memory still ran out, and the laptop was down for 13 minutes (see "A laptop that ran out of memory") |
| The room carries what the seats say and the files they write, not every command | `bin/acp-quiet` (on by default; `ACP_QUIET_LEAN=0` posts everything) | Band's free plan stores at most 10,000 messages in a room and then refuses every post, for good. The run before the submitted one reached that ten working hours in, in the middle of stage 2: two-thirds of its room were tool calls and their results. Now the room gets each seat's messages, its file writes and edits, and the filter's own pause notes; thoughts, shell commands, reads and searches, and their output stay in the seat's runtime record, where `bin/meter` and `bin/access-audit` read them. The submitted run's room held 4,833 messages when stage 4 closed. The cost: the room no longer shows the commands themselves; the Builder's handoffs carry the exact commands it ran and their results, as its mandate asks |

One gap remains: the runtime's search tool is matched on the search text, not the folder, so it cannot be fenced by path. `bin/access-audit` lists every seat tool call that reached the check files, refused or not, from the seats' own records.

## Who talks to whom

```text
human ──dispatch (once, all stages)──▶ Foreman
Foreman ──complete requirements──▶ Adversary      (before any code: the ledger)
Foreman ──complete requirements + work items──▶ Builder, Finisher
Builder / Finisher ──commit hash + evidence──▶ Adversary, Foreman
Adversary ──PASS / BLOCKED + failing rows──▶ Foreman, Builder / Finisher
Foreman ──accepted commit──▶ Saboteur ──caught X of N, missed rows──▶ Adversary, Foreman
Foreman ──final report──▶ human
```

A seat sees only the messages that @mention it, so every handoff carries the complete requirements verbatim. The Adversary is never on implementation chatter; the builders are never on the verdict.

## What breaks without the room

Without Band there is no path for a verdict to block a commit, no way for the Adversary to receive requirements before code exists, and no record that ties each commit to the discussion that produced it. The room is the only channel between seats.

## Stand it up

Needs, before step 1:

- Linux with a user systemd session (`systemd-run --user` keeps the daemon and the host services running after the terminal closes).
- Band Desktop, signed in. It installs the `band` command and Band's daemon, `jamd` (tested with 0.4.12).
- Docker, with your user in the `docker` group (`sudo usermod -aG docker $USER`, then log out and back in). The seats start containers through it.
- `bwrap` (the `bubblewrap` package), Node.js 18 or newer with npm (tested with 22), Python 3.12 or newer, and `~/.local/bin` on your `PATH`.
- Language toolchains and a headless browser installed system-wide (under `/usr/bin` or `/usr/local/bin`). A seat's jail hides your home folder, so a toolchain installed there (nvm, rustup, pyenv) is invisible to the seats; the one exception is the Playwright browser cache, `~/.cache/ms-playwright`, which step 0 fills.
- OpenCode 1.18.33 (step 1), the version the protocol filter and the model switch were tested against.

No model account, key or card: every model named in `mandates/` is a free OpenCode model that works without sign-in. Run every command below from this folder (the one holding this file).

A seat can instead name an NVIDIA-hosted model (`Model: nvidia/<model>`), which needs a free NVIDIA Build key (no card) on one line of `~/.config/band-hack/keys.env` (`NVIDIA_API_KEY=…`, file mode 600). `bin/stand-up` then starts `bin/key-proxy`, and `bin/preflight-run` refuses to start a run if the proxy is not answering.

`bin/stand-up` also starts `bin/wake-seats` (a user service, no root), which wakes a seat once its model is back after a usage limit, and `bin/mem-guard`, which removes services and containers the seats left running; `bin/preflight-run` refuses to start a run without either.

```sh
# 0. The event's kickoff repository: the specifications, and the harness that runs the supplied checks.
#    This folder is <spec dir> below. Seats read it read-only and run the checks with its .venv;
#    bin/preflight-run also scans the mandates with its vocabulary check.
git clone https://github.com/band-ai/dark-factory-wearedevs <spec dir>
( cd <spec dir> && python3.12 -m venv .venv && .venv/bin/pip install -r harness/requirements.txt \
    && .venv/bin/python -m playwright install chromium )

# 1. Tools (no root needed for OpenCode)
npm install --prefix ~/.local/share/opencode-tools opencode-ai@1.18.33
mkdir -p ~/.local/bin && ln -s ~/.local/share/opencode-tools/node_modules/.bin/opencode ~/.local/bin/opencode
band init                                   # sign in to Band once, in the browser

# 2. The Band daemon, able to reach Docker, with idle seats parked and no waiting on humans.
#    Band 0.4.12 polls each running seat's output in a busy loop (about 1.2 cores per seat on 8
#    workers); two worker threads cap that at 2 cores with no slower room reads (measured 1 Oct).
#    A daemon already running (for example one Band Desktop started) lacks these settings, and
#    bin/preflight-run refuses it: stop it first.
band daemon status && band daemon stop
systemd-run --user --unit=band-jamd --setenv=TOKIO_WORKER_THREADS=2 \
  --setenv=JAM_OWNED_RUNTIME_IDLE_SECS=900 --setenv=JAM_QUESTION_TIMEOUT_SECS=60 "$(command -v jamd)"
band daemon status                          # should report it running
#    (If the user service cannot reach Docker because you joined the group in this login session:
#     TOKIO_WORKER_THREADS=2 JAM_OWNED_RUNTIME_IDLE_SECS=900 JAM_QUESTION_TIMEOUT_SECS=60 \
#       setsid nohup sg docker -c 'band daemon run' >>~/band-daemon.log 2>&1 &)

# 3. One seat per mandate: jailed launcher, model from the mandate, mandate attached
bin/stand-up --owner <your Band username> --work <absolute work dir> --kickoff <absolute spec dir>

# 4. Before every run: the run's repository first (inside a seat the work area's root is read-only,
#    and only folders that exist when the seat starts are writable), then fresh seats, then the check
git init -b main <work dir>/<repo> && mkdir -p <work dir>/checks/<repo>
bin/stop-seats && for s in foreman builder finisher adversary saboteur; do band onboard --session df-$s; done
RUN_REPO=<repo> bin/preflight-run --fix     # every line [ok] before you go on

#    Keep the machine awake for the whole run, in a terminal you leave open (on a laptop a closed
#    lid suspends it even with the desktop's keep-awake setting):
systemd-inhibit --what=handle-lid-switch:sleep --why="run in progress" sleep infinity
#    On Wi-Fi, keep it rejoining the network if the network drops out (see "A hotspot that disappeared"):
systemd-run --user --unit=band-net-watch "$PWD/bin/net-watch"

# 5. A room with every seat and you in it, then the one message of the run
room=$(bin/open-room --owner <your Band username>)
RUN_REPO=<repository folder> STAGES=1-4 bin/dispatch "$room" dispatch/tablekeeper.md.tmpl
#    (fills in the repository, check folder, specification path, stages and your handle;
#     dispatch/toy-stage-1.md.tmpl is the same for the small practice problem)
#    Within a few minutes the Foreman posts its plan. Follow the room in Band Desktop, or in a
#    terminal with bin/watch-room "$room". Send nothing more: the dispatch is the run's only human input.
```

Pointing it at another of the event's problems changes only the task file in step 5 (see *Pointing it at a different problem* at the end).

If the machine restarts during a run: `bin/resume-host`, then let the seats carry on (see "A laptop that restarted mid-run" below). To end a run: `bin/end-run <room>`. While the seats are still running and idle, it removes every seat but the coordinating one from the room (`band chat remove --session df-foreman <room> <owner>/<seat>`) and detaches each seat's session for that room (`band detach --session df-<seat> --host-session default-<room>`); and only then runs `bin/stop-seats` (stops every seat, then terminates any runtime that outlived the stop). In that order: a seat keeps one session per room it was ever in, starting a seat resumes all of them, and an old message then pulls the seat back into the finished room — in practice the coordinating seat began the next task inside the old room and re-added the others to it. A detach made after the stop did not hold, and a detach times out while a turn is running. To read a run afterwards (`room.json` is the room's full session: Band Desktop → the room's ⋮ menu → Open in Band → ⋮ → Download → Download full session): `bin/meter <seats…> --since <dispatch time>` for time and spend per seat, `bin/teamwork-audit room.json <result repo>` for who did the work, which commits the room names, the verdicts, and every human message, and `bin/access-audit --since <dispatch time> <seats…>` for every attempt to reach the check files.

## Design choices and what they cost

| Choice | Why | Cost |
|---|---|---|
| Adversary writes its ledger **before** seeing code | Checks come from the requirements, not from the implementer's reading of them; shipped checks are a sample (as low as 11% at one stage) | A full extra read of every specification |
| The checker runs the **same model** as the builder; its independence comes from a ledger written from the specification before any code exists, and from the Saboteur measuring it | Two faster free models failed as the checker in practice runs: one timed out mid-thought, one posted garbled text in its first turn. A checker that fails in the room is worse than one that shares the builder's model | A model's blind spots can repeat in its own review — the Saboteur measures how often instead of assuming it away |
| Models chosen by a **measured solo trial**, then a practice run: each candidate alone gets the stage-1 specification and is graded by the supplied checks | Picks from evidence, not reputation: the chosen model scored 120/120 alone. A trial is necessary, not sufficient — a model that scored 116/120 alone degenerated in its first real seat turn | One trial run per candidate model, plus a practice run |
| Every seat on the shared model names a **second model on a separate quota** and carries on with it while the first is capped | The free gateway caps a model after about a thousand requests from all seats together (measured: 980, 1,015 and 1,006 requests at three caps) and lifts the cap one to four hours later; with four seats on one quota the factory spent more time waiting than working | The second model is weaker (116/120 alone on stage 1, against 120/120), and a turn can finish on a different model than it started on — the checker's ledger and the Saboteur are what catch a weaker result |
| A seat that **audits the checker** (Saboteur) | A checker that passes broken work is invisible until it matters; planted defects measure it. In the submitted run's stage 1 its first table showed that the Adversary's probe script for those defects was still a placeholder that caught none of them; the Adversary then wrote a probe for each and ran the event's harness against each defect: the shipped checks caught 8 of 11, its probes 11 of 11 | Extra builds and runs per stage. In the submitted run, re-measuring the stage-1 defects started a service per defect on a 7 GB laptop already short of memory, and memory ran out (see "A laptop that ran out of memory"); the Foreman held stage 3 until the stage-2 table was committed, though its mandate says not to wait; and the Saboteur's model, the only one no other seat shares, was rate-limited for most of stage 4, so the Foreman ran that round itself |
| Every handoff pastes the complete requirements | Seats cannot read the room; a summary loses sentences, and every sentence is a test | Long messages, more input tokens |
| Seats **never open the supplied check files** — they run them and read only the results, and the runtime refuses the rest | Checks cover a sample of the specification; code shaped by the sample overfits it, and the event disqualifies code written to the tests. A development run caught a builder reading the check files first — the rule came from that | Interfaces must be inferred from the specification alone, so the first build is slower |
| Per-seat git identity | The history shows who wrote what; nothing reads as hand-written | None |
| Free models only | Anyone can stand the factory up with no budget | Weaker models than paid frontier ones; the verification loop has to make up the difference. Two of the three are hosted free-tier models whose weights are not published (only the Saboteur's Nemotron is open-weight), so their availability is the host's to change; any OpenCode model drops in by name in the mandates |

## How the factory catches and recovers from bad work

Stage 1 of the submitted run (3 October, times UTC; room log and git history):

- **The ledger first, then an acceptance without the checker.** The Adversary committed its stage-1 ledger, written from the specification, at 09:58 (`3894e50`), before any stage-1 file; the Builder's service followed at 10:54 (`89298a3`). The Foreman built it and ran the supplied checks itself: 116 of 120, and it sent the Builder the two defects behind the four failures, with the failing check names, at 10:58. At 11:39 the Adversary posted BLOCKED on `c1e5735` without a reproduction, saying in the same message that it had not checked the full ledger. Three minutes later the Foreman accepted `c1e5735` on its own evidence (twelve probes of its own, and the supplied checks at 120 of 120 on the host and isolated) and wrote the gap into the record: "the adversary produced no usable independent verdict for stage 1". The mandates say a stage is accepted when the Adversary passes it; this one was not (see *What we tried that failed*).
- **The Saboteur measured the checker, and the checker caught up.** The Saboteur's first table on `c1e5735` (12:51, `aaf8e7d`) found that the Adversary's probe script for its defects was still a placeholder: of 12 defects, the Adversary's side caught one, and that one with a probe of the Foreman's. The Adversary wrote a probe for each of 11 (`4fc3512`, `778cfc2`), then ran the event's harness, isolated, against each defect (`4540b2b`, 14:13): **the shipped checks caught 8 of 11, its probes 11 of 11.** Each of the three the shipped checks pass breaks a requirement the specification states: a replayed idempotency key racing its own first write (the losers must get the winner's body, byte for byte), an import that merges into the existing state instead of replacing it, and a batch of table moves applied one by one instead of all or nothing. Its own caveat: these are its versions of the Saboteur's defects, and one is harsher than the original, so the number of checks it fails overstates how well they see it.

Stage 2 of the submitted run (3 October):

- **The one ledger that came second.** The stage-2 folder was a copy of stage 1 (11:52); the Finisher committed its first stage-2 change at 12:00, and the Adversary's ledger followed at 12:04 (`f8f48d7`).
- **The supplied checks passed; the checker blocked on what they do not ask.** After the supplied stage-2 checks failed on three screen states at `bacee63`, the Adversary blocked there too (14:29, `0489981`: three rows, one cause, reproduced), and the Finisher fixed them by 14:44. ## What we tried that failed

- **Models that do not use their tools.** In a solo bake-off on the stage-1 specification, two free models (MiMo V2.6 Flash, LongCat 2.5) printed the whole program as chat text and never wrote a file. A seat that does not act is worse than no seat; both were dropped.
- **A seat started with an empty argument.** Giving Band a custom launcher without the runtime's `acp` argument left two seats silent while their handoffs queued. Fixed by always passing the argument; the launcher now logs every start.
- **Acknowledgement loops.** In the first practice run the work was accepted in ten minutes, and then three seats spent the next minute thanking each other — "Acknowledged." answered by "Acknowledged." — until the workers were stopped by hand. Every mandate now forbids sending or answering an acknowledgement: a seat messages another only with new work, new evidence, a verdict, or a question it must answer.
- **Polling instead of waiting.** The first Foreman watched an empty folder with `sleep 30` while the builder worked, burning turns. Band wakes a seat when it is mentioned, so every mandate now says: after a handoff, end your turn.
- **Handoffs through a shell command line.** The first Foreman posted a 19 KB specification by putting it inside a quoted shell argument. Its backticks made the shell fail (`unexpected EOF`), and nothing was sent — a handoff that silently never happened. Every mandate now says: write multi-line messages to a file and send them with `--body-file`, then check the send succeeded. The retried handoff arrived whole: 21,252 characters, every backtick intact.
- **Old rooms coming back.** Reviving the seats after the practice run also revived their practice-room sessions: the practice Foreman carried on to a stage it had been told not to build, while the real room waited. Before a run, every seat is now detached from every earlier room.
- **A coordinator that did the work itself, out of sight.** In a development run the Foreman used its runtime's built-in subagent tool to start a helper told "you are the Builder". The helper wrote the service in the same folder as the real Builder; the Builder watched its files vanish and foreign ones appear, and retreated to a private folder. The subagent tool is now removed from every seat.
- **A builder that read the checks.** The same run's Builder read the supplied check files before writing code, and later ran the test runner on them directly; the development dispatch had named their folder. The dispatch no longer names it, and the runtime now refuses every open, listing and print of those files (see above).
- **The jail that hid the checks' own tools.** The seat jail hid the user's home, including the Python the checks' environment points to and — after a reboot before a group change took effect — access to Docker. Seats could not run the checks at all. The launcher now exposes that interpreter read-only and re-enters the Docker group, and the pre-run check tests both from inside a seat.
- **A written rule the coordinator ignored.** Even with the file rule in its mandate, a later Foreman again posted a specification inline; the shell ran its backticks and the Adversary received a gutted handoff. The runtime now refuses any send with newlines, backticks or `$(` on the command line.
- **A rule that a later rule undid (the 1–2 October run).** The runtime applies the last rule that matches a command. The refusal of inline messages was written before the rule that lets a seat name its own session (`--session df-<seat>`), and nearly every send names it (110 of 113 in this run), so the refusal never applied. Two of the Saboteur's reports went out inline with backticks: on 1 October at 17:01 UTC the shell ran eight backticked words as commands before the send (a clean resend from a file followed two minutes later), and on 2 October at 10:29 its stage-2 report reached the room reading "until a handler gains an ." where it had written `await`. The Foreman sent twelve multi-line messages inline; none held anything the shell could run. Since then the identity rules come first and the message rules after them; a test evaluates eleven sends against both orders with the runtime's own matching: the old order lets four through, the new one none.
- **A lead that took the end of a stage for the end of the task (the 1–2 October run).** The Foreman's mandate said when a stage is done, then "if the task has a next stage", how to start it, and separately to post one final report "when the task is done or cannot proceed". Stage 2 was accepted without the word PASS, as a decision of the Foreman's, and once the Saboteur's table and its triage were in, the Foreman posted its final report on stage 2 and closed three turns calling the work complete. Every handoff is the Foreman's, so the run stood at 2 of 4 with every seat idle and nothing failing. Since then the Foreman's mandate says to start the next stage in the same turn as it hands the accepted one to the Saboteur, without waiting for the table, and that the task is done only when the last stage is passed; and the Builder's copy of a stage folder includes rewriting the folder names in its run file. The submitted run went through all four stages, though the Foreman still held stage 3 for the stage-2 table (see "A lead that waited for the defect table").
- **Leftovers from an earlier run.** Handoff files were written into the shared work area, and the next run's Adversary found the previous run's file, took it for its task and set off to verify the previous run's repository. Message files now go to each seat's private `/tmp`, earlier runs are moved out of the work area, and the pre-run check fails if anything is left.
- **Two seats thanking each other forever, again.** Band tells each seat to finish a turn that needs no answer "without emitting an assistant message". The models could not: the Foreman and the Finisher traded "No reply needed." and "Silent completion." ten times in twenty seconds, each post waking the other. A rule in the mandates had not stopped it, so the fix went below the model: seats close such a turn with SILENT, and a filter on the protocol stream turns that into a silent completion (tested on the live runtime: the sentinel turn reached Band empty, the next turn's reply intact).
- **Files written in the shared working directory.** Every seat starts in the shared work area, so "save the ledger in `verification/`" put the Adversary's ledger outside the repository, uncommitted. The mandates now name `<result repository>/verification/` and say that every file goes inside the repository or `/tmp`.
- **A language with no toolchain on the machine.** A Foreman chose a compiled language that was not installed; the Builder could only compile inside a container, hit a broken link step in the toolchain image, and lost ten minutes on it. The Foreman now checks what is installed before choosing.
- **A stop that did not stop.** Band reported that it could not stop one seat's runtime, and that runtime went on writing into the finished run's repository after it had been archived. `bin/stop-seats` now stops every seat and then terminates any seat runtime still alive.
- **A checker that committed other seats' work.** The Adversary staged everything before committing its ledger, and two of its commits carried the Builder's time-zone module and the Finisher's stylesheet. Each seat's git now runs a read-only commit hook that refuses files outside the seat's area, and bulk staging is refused.
- **Garbage from the free gateway.** Twice, a free model's reply was a stream of fragments in six writing systems — once posted to the room as the checker's answer. It is not one model: the same pattern came back from the builder's model in a test. The protocol filter now withholds such text and asks the sender to resend. The detector was checked against every text the seats had written: it flags only the degenerate ones.
- **A seat's private notes posted as a reply.** When a session grows long the runtime compacts it, and the summary it writes for itself streams out like any reply. Twice in one morning the Foreman's 10 KB summary went to the Finisher as a message; the Finisher answered it as a brief with two problems. The filter now withholds text in the runtime's summary template. The same practice run showed seats leaving a check service running after every check — about 270 MB each — until memory and swap filled and the desktop client was killed; `bin/mem-guard` now removes what seats leave behind and the mandates say to stop what you start.
- **A model that fell apart.** A free model that scored 116/120 alone on stage 1 produced garbled text in its first turn as the checker — and the room received it. It was dropped; a solo score is now only the first filter.
- **A model that goes quiet.** One free model thinks silently for minutes before writing a long document; the free gateway drops idle connections (`504 Upstream idle timeout`) and the automatic retry repeats the same long think. The checker stalled three times in five minutes. It moved to a model that streams steadily, and every mandate now asks for large files in parts of about a hundred lines.
- **Seats that dropped out on a rate limit.** Seventy minutes into a development run, with four seats on one free model, the gateway began refusing that model (HTTP 429, no retry time given; still refused a quarter of an hour later, while another free model answered normally). The runtime retried for a minute and failed the turn; Band stopped the Builder's and the checker's runtimes — the checker minutes before its verdict. Nothing in the room said why. The protocol filter now pauses a rate-limited turn, says so in the room, and resumes it on its own. Pausing only waits the limit out; the lasting fix is less load on one quota — each seat on the shared model now names a second model on a separate quota and carries on with it while the first is capped, and goes back once the first answers again.
- **A restart that forgot everything.** When Band brought the two stopped seats back, it started each in a fresh runtime session: the seat got its mandate and the requirements it had been handed, but none of its own earlier work — the checker did not know it was minutes from a verdict. Its records were still on disk, just not in the new session. Every mandate now says how to recover: `band brief` for the room and the messages sent to you, then the room's messages, the repository's history and your own files, before acting.
- **A provider that cuts long replies.** Through NVIDIA's free endpoint, a reply that calls a tool is held back until the call is complete, and a reply still unfinished after about five minutes simply ends. A model asked to build the service alone tried to write it as one file, was cut every time, and the runtime retried the same step for twenty minutes without writing a line. Asked for files of at most about 250 lines, the same model wrote the service as ten files within fifteen minutes. Every mandate already asks seats to write large files in parts.
- **A model that killed its own runtime.** Restarting its server, a model ran `pkill -f "python3 app.py"`. The runtime's own command line held the task text, which named that command, so the runtime was killed mid-run — and three solo trials ended that way before we noticed. Trials now pass the task in a file, and every seat runs in its own process space.
- **A checker on a faster, separately-hosted model.** To give the checker its own quota we moved it, mid-run, to Nemotron 3 Ultra on NVIDIA's free endpoint. Within fifteen minutes it had checked out an old commit inside the shared repository, written check results where the isolated run could not read them, and begun rewriting the existing ledger in one oversized step. It went back to the builder's model; the checkout rule above came from this.
- **A defect table that was never committed.** In the same run the Saboteur wrote its table of planted defects into the repository and reported the totals, but never committed the file; had the run ended there, the evidence would have been lost. Its mandate now says to commit the table before sending anything about it and to name that commit in the message, and the Foreman does not close a stage until the table's commit is named in the room.
- **A mention that woke no one.** In the practice run on a second problem, six of 46 messages named the Builder at the end of a sentence. Band read the full stop as part of the handle, found no such seat, posted the handle as plain text and woke no one; the Finisher concluded the Builder was unreachable and asked the Foreman to relay. The mandates themselves had four handles written straight before a full stop, comma or semicolon, and the models copied the pattern. Those sentences are reworded, and every mandate now says that a handle needs a space or a line break after it, and to correct and resend when the send warns that a handle was left as literal text.
- **Screens written for the builder, not the person.** The first practice interface passed its own checks at both widths and still read like a debugging tool: sign-in offered to someone already signed in, a party size of four searched and two pre-filled on the booking form, a hint explaining that changing a field "rotates the request key", two primary buttons side by side in the uncertain state, a refusal that said only "some of those details were not accepted", dates in data format, "stage 2" in the footer, and a grid cut off at 375 pixels. The Finisher's mandate now says: write every word for the person, show only the actions that apply in the current state, carry forward what the person entered, say what was wrong next to the input it concerns, reshape rather than cut off at narrow widths, and read each state's visible text back before handing off; the Adversary checks the same on every screen.
- **Paid providers without a card.** A cloud account without a payment method showed every open-weight model with a zero daily quota. The factory was redesigned around free tiers instead.

**From the full run before the 1–2 October one** (same problem, same factory; ended after six hours with stage 1 not yet accepted, and replaced by the 1–2 October run with the fixes below in place):

- **Messages that waited behind a long turn.** A seat receives messages only between turns, one per turn, oldest first, and nothing in a delivered message says when it was sent. The Builder's first turn ran 40 minutes, so the Finisher's brief reached it 39 minutes late. The Builder's queue never recovered: five hours in, 49 messages were waiting and the one it was handed had been sent 4 h 21 min earlier. Its answers to stale prompts reopened closed work ("nine findings, all still open"), and it applied an instruction the Foreman had withdrawn 50 minutes earlier, because the withdrawal was still in its queue. The Foreman read the silence as loss and re-sent, which made the queues longer. Measured by comparing each seat's runtime database (the prompts it received) with the room log. Now every mandate says a silent seat is working, to read newer messages first and answer superseded ones with SILENT, and that the Foreman never re-sends. The protocol filter also folds a queue into one turn: a message that arrives right after the previous turn ended was waiting, so it is delivered together with every newer message to that seat, each with its send time, and those messages are settled without the model when their turn comes. Replayed on the Builder's real queue (50 messages, 147 KB), that is 3 model turns instead of 50 (filter test: 13 of 13 cases; a failed room read delivers the message as it came). In the 1–2 October run the Builder's brief waited 52 minutes behind its first turn; it arrived with the one newer message, the Builder answered once ("stage 1 is complete and passing") instead of rebuilding, and the newer message was settled without the model.

- **A seat speaking as another.** After its conversation was summarised, the Adversary forgot its own session flag, found a plain send refused ("peer not found"), and posted its verdict with `--as` as the Foreman and as the Builder: four messages in 44 seconds. The Foreman then had to argue out who had written a verdict signed "Builder". The launcher now sets each seat's own Band session, and the runtime refuses `--as` and any other seat's session (tested against the Adversary's exact commands).

- **Reports for a reader who is not there.** After sending its messages, the Foreman often ended a turn with a report addressed to nobody in particular ("Broke the loop with a blunt stop… Three things went out:"). The runtime posts a turn's closing text as a reply, so each report reached the seat that had started the turn: 9 of the Foreman's first 30 sending turns, then every one from the fifth hour on, 65 of 86 by then (83 KB). Each Foreman instruction reached its reader as two messages, doubling that reader's queue. Two of these reports asked the absent human whether to reassign work. Now, after a send, any closing text is shown in the room as a thought and delivered to no seat (filter test: 20 of 20 cases). In the 1–2 October run the Builder's 806-character "Stage 1 is complete and handed off" report became a thought instead of a second message to the Foreman.

- **Silence that was posted.** A seat with nothing to add often wrote so instead of ending with SILENT: "*No reply — noted; standing by for the consolidated hash.*" The Adversary posted 16 of these in 40 minutes, each one waking the Foreman; later the Foreman posted "Silent. The four operating rules are a receipt of my own rulings…" twice in 30 seconds (599 and 689 characters), each waking the Adversary. A short closing text that opens with "No reply" or "Silent" followed directly by punctuation now counts as silence, and a longer one is shown as a thought; "No reply from the Builder in 20 minutes, so…" and "Silent failures in p12…" stay messages (filter test: 20 of 20 cases).

- **A command that killed itself.** The Builder started the service in the background, ran its tests, stopped the service with `pkill -9 -f "node src/index.js"` and meant to run the supplied checks next, all in one shell command. The pattern also matched that shell's own command line, so the pkill killed it; the checks never ran, and the runtime waited on a command that no longer existed until its 30-minute timeout. A private process space per seat protects the runtime from other seats, not a command from itself. The runtime now refuses `pkill -f`, and the mandates say to stop a process by the id saved when it started. In the 1–2 October run the runtime refused the Builder's `pkill -f "^node src/index.js"` during its first turn, and the turn went on.

- **Narration posted as messages.** Before acting, the Foreman often wrote one line on what it was about to do ("Resending a compact dispatch instead."). Each line was posted as a message and woke the seat it named. A single short line streamed right before a tool call is now shown as a thought, still visible in the room; in the 1–2 October run's first hour, eleven such lines became thoughts.

- **A daemon that spun through the run.** Band's daemon, which relays every message, was stuck in a busy loop for the whole run: it used 41.7 CPU-hours in the 8.75 hours the machine was awake, 4.8 of the machine's 8 cores on average, and the seats, their checks and their containers shared what was left. Nothing logged it. Traced afterwards: for every running seat, the daemon re-reads that seat's output and error pipes in a loop and gets "no data yet" each time, about 1.2 cores per seat. A fake seat runtime started without our jail, filter or error output spun it the same way, so the fault is in Band 0.4.12. The daemon now runs with two worker threads, which caps the loop at 2 cores with room reads no slower (three seats: 364 % → 200 %), and `bin/preflight-run` refuses to start a run while the daemon spins at rest or runs without the cap. In the 1–2 October run, with five seats working, it held at 200 %.

- **A network drop that ended the run.** Six hours in, the laptop's connection (a phone hotspot) dropped for 75 minutes. The seats' model requests failed with "Cannot connect to API: Unable to connect", and the filter passed that failure on to Band as it did any error it did not recognise. Band treated each runtime as crashed and started the three working seats again on new, empty sessions: the Foreman's 861-message conversation, the Builder's 514 and the Adversary's 1,035 were no longer attached. It never re-delivered the ~100 messages that were waiting, so when the connection came back nothing woke any seat. A turn that fails for lack of a network is now held open like a rate-limited one: the room gets one note, the filter retries with growing pauses for up to about four hours, and the turn carries on in the same session once the connection is back; any other error still reaches Band at once (filter test: 6 of 6 cases).

- **An ended room that came back.** After that run was ended and the daemon restarted, bringing the Foreman back online re-created its session for the ended room, which it still owned, and Band delivered the 20 messages still queued for it there. The Foreman spent four minutes on one of them in the ended room, searching the disk for the old run's files, before it was stopped. `bin/end-run` now settles every seat's queued messages for the room before it stops the seats.

- **A laptop that slept mid-run.** Closing the lid suspended the machine for 97 minutes, even with keep-awake on. On waking, one model request hung until the runtime retried it 5 minutes later, and the memory guard counted the sleep as age and removed a live check container. The lid switch is now inhibited for the whole run; the memory guard restarts its clocks after any wall-clock jump; and `bin/meter` cuts suspends out of every seat's working time, from the kernel's own record.

- **A laptop that restarted mid-run (the 1–2 October run).** Three hours and fifteen minutes in, the laptop was restarted from the desktop's power menu while the Adversary was re-verifying the stage-1 head and the Builder was extending its own tests. Band's daemon, every seat and the host services stopped, and the run stood still for 2 h 30 min until the daemon was started again (step 2 above, the memory guard and the wake service as `bin/stand-up` starts them); no message was posted and no seat was touched. The daemon brought all five seats back by itself, but none of them got its conversation back: Band starts a new, empty runtime session whenever it starts a seat's runtime again, the same path as the network drop above. The two seats that were inside a turn restarted at once (the Builder's 426-message conversation and the Adversary's 279 were no longer attached); each idle seat started afresh when it was next woken, the Foreman twelve minutes later (99 messages), the Saboteur when it was briefed after the stage was accepted. The run carried on because none of its state lives only in a seat's conversation: the mandates' recovery rule sends a seat to the room first, and work in progress was still in the repository's working tree. Six minutes after the restart both new sessions had committed the work their predecessors left unfinished; at twelve minutes the Builder posted a full report listing every commit since its last message, and at fourteen the Foreman named the new head for verification. What a restart still costs: every seat loses its conversation. Bringing the host back is now one command, `bin/resume-host`: it starts the daemon with the run's settings and the host services if they are not running, says whether the lid is still inhibited, and lists the seats; it posts nothing and touches no seat.

- **A hotspot that disappeared overnight (the 1–2 October run).** Nine and a half hours in, at night, the phone hotspot the laptop was on stopped answering. The machine's network manager tried to reconnect, asked for the Wi-Fi password, got no answer within two minutes, and then stopped trying: it would have stayed offline even with the hotspot back. Only the Adversary was inside a turn, verifying stage 2. The filter held that turn open as it was built to, six retries over 39 minutes with nothing passed on to Band as a crash, but 73 minutes after the drop the laptop was suspended and came back as a fresh boot, which ended the turn. The run stood still for 10 h 03 min. Bringing it back exposed a fault in `bin/resume-host`: `band daemon status` exits with success and prints "daemon not running" when the daemon is down, so the script reported it running; it now reads what the command says. Once started, the daemon re-delivered the 10 messages the Adversary had not acknowledged and started its seat 12 seconds later, so the run resumed with the seat the others were waiting on. Seven minutes after the restart the new session committed the work its predecessor had left in the tree, and 60 minutes after it wrote its verdict, which is the next entry. Now `bin/net-watch` runs beside the seats (`bin/resume-host` starts it): when Band has been unreachable for two minutes and the Wi-Fi is not connected, it rejoins the saved network, which clears the network manager's block; it changes no setting, and it leaves the network alone when Wi-Fi was switched off by hand. In the submitted run the hotspot was switched off for a planned hour: the one turn in flight, the Builder's, failed six times for want of a network and was held open each time, 71 minutes in all, and it carried on in the same session 18 minutes after the network came back, at the end of its last pause.

- **A verdict the filter swallowed (the 1–2 October run).** After the overnight restart the Adversary's new session began, as its mandate says, by reading the room, and the listing it printed quoted the Foreman's earlier send commands (`jam … send <room> …`). The filter treats a turn that has already posted through the command line as done talking, and turns its closing text into a thought so the room does not get the same report twice. It looked for that send in everything the runtime reported, the command's output included, so it took the quoted commands for the Adversary's own, and the stage-2 verdict, BLOCKED on four rows with the supplied checks passing, went out as a thought, which wakes nobody. The Adversary's next message went to the Saboteur, the Saboteur ended its turn silently, and at 06:11 UTC every seat was idle with the verdict undelivered: a stall that nothing inside the room could break. Before anything was posted the filter was fixed: it now reads only the command a seat ran, and a send that failed does not count. A new filter test replays the case (the old filter fails it, the fix passes, and the earlier filter tests still pass), and each seat picks up the fix when its runtime next starts. Then, 34 minutes into the stall, the run's second human message relayed the verdict to the Foreman in one sentence: what it was, the file it is in, and that nothing else would follow. The Foreman's first answer was empty, and the filter's rule that a human's message is never answered with silence sent it back once; its second turn went to work on the verdict. What it cost: an hour between the verdict and the Foreman reading it, and the claim of a single human message. With the verdict in hand, the Foreman routed the four rows at 07:18, after first trying to make two of the fixes itself (see the next entry); the Builder and the Finisher had fixed them by 07:56, and by 08:23 the Adversary had re-verified both fixes, retracted two of its own failures as a probe error, and found a deeper defect on the upgrade path (see "Stage 2 of the 1–2 October run").

- **A side door to the check files (the 1–2 October run).** On 1 October at 17:37–17:38 UTC, building the stage-2 screens, the Finisher changed into the specification package's track folder, listed `test`, and printed the first 200 lines of the stage-2 browser checks and the shared fixture file, twelve minutes before its screens commit `bf4afc9`. Our own audit matched the folder's name too, so it first reported four of the ten; widened, it reports all ten and nothing else. Since then the runtime also refuses the check folders as a destination (`cd`, `pushd`, a working directory) and the folder-relative names, and the audit reads both forms. In the submitted run it refused 12 attempts by three seats, and no seat read a check file.
- **A planner that went around its rule (the 1–2 October run).** Working through the relayed stage-2 verdict, the Foreman tried to make two of the fixes itself. The runtime refused its edit of the Builder's `stage-2/src/routes.js`, as the rule says; its very next command was a short Python script, commented "since bash tools are restricted from editing stage files", that wrote the change anyway, and it then changed the Finisher's `stage-2/public/home.js` the same way. ## Pointing it at a different problem

Write a new dispatch. Nothing else changes — not the mandates, not the launcher. For a problem outside this event, the dispatch names that problem's own checks, and `bin/preflight-run`'s two checks that use the event's harness (a seat can run it; the mandates pass its vocabulary scan) report failures you can read as notices.

We did this on 30 September with the event's practice problem (a small counter service; `dispatch/toy-stage-1.md.tmpl`): the five mandate files that had just run stage 1 of this track, unchanged, in a fresh room and a fresh repository, with one message in. What happened, from the room log and the git history:

- The Adversary committed a requirements ledger before any code existed (26 rows; one was later split in two); the Builder built the service; the Adversary committed a 33-assertion probe script and passed the candidate from a fresh clone. With no screens in the stage, the Finisher reviewed the run instructions and error messages and proposed ten wording changes, and the Builder applied them; the Adversary re-verified and passed again.
- The Saboteur planted 14 defects in scratch copies. **The supplied checks caught 9; the Adversary's probes caught 11.** For the three that neither caught — a missing lock, a reset that answers before it assigns, state that survives a restart — the Adversary added probes (66 assertions in all) until **all 14 were caught**, and said plainly where a probe has to read the source because no request can observe the fault.
- The Foreman posted the final report 1 hour 40 minutes after the dispatch. One human message in the room; every commit named in a seat's message; 0 completed reads of the check files (1 attempt refused by the runtime); 451 model turns, 2.2 M fresh input and 17.0 M cached input tokens, $0.00.
- Our own run of the event's harness on a clean clone, in isolated mode: stage 1 claimed, 100% of its suite.
- It ran almost entirely on the second model: the first was still capped from the morning's run, so the four seats that share it made 248 requests on the second and 5 on the first. The factory did not wait for the cap to lift.

It also surfaced two faults, both since fixed in the mandates (see *What we tried that failed*: the mention that woke no one, and a defect table left uncommitted). The mandates submitted with this entry differ from the ones in the toy run by those fixes, by rules for screens drawn from the practice run's interface, and by the changes the later runs taught, each in *What we tried that failed*.
